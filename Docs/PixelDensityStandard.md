# OnAir 物体像素密度标准 v1

基准：用户认可的原有楼房颗粒度。不是声称与《西奥小镇》内部参数完全相同。

## 一条核心规则

固定游戏正交视角下，每投影世界单位4个物体像素，即一个像素覆盖0.25个投影世界单位。大楼使用更大的像素画布，不使用更密的像素；小屋使用较小画布。屏幕分辨率和相机远近会改变最终显示大小，但同镜头中的资产颗粒尺度应一致。

统一参数由 Assets/Scripts/World/PixelArtStandard.cs 定义。PixelObjectBaker 不接受按资产覆盖密度。

## 各类资产如何应用

| 类别 | 制作约定 | 当前状态 |
| --- | --- | --- |
| 新旧建筑 | 4 PPU，保留四向颜色、法线、深度和独立窗户编号 | 统一重建与检查 |
| 树木等独立环境物体 | 同建筑密度；大小变化在源模型中制作后重绘，不能缩放成品像素图 | 现有两种树使用原生尺寸，取消每实例0.8—1.39倍缩放 |
| 未来路灯、车、护栏、广告牌等独立像素资产 | 同一密度；无法读清的细节合并成色块，必要时适度夸张体块 | 新资产准入规则 |
| 道路、桥梁、地形、岸线、水面 | 目前仍为程序化几何和大色面，没有统一的物体像素贴图；未来增加空间纹理时使用同一世界尺度 | 不宣称这些几何已经全部改成像素图；不为凑颗粒添加噪点 |
| 坡面色彩渐变 | 现有一维渐变是地形颜色查找表，不是按世界面积铺贴的纹理 | 不用其128像素长度计算空间颗粒度 |
| 飞机、粒子、UI和字体 | 动态主体与屏幕界面单独管理；不擅自扩大这次楼房修正到交互和运动系统 | 后续独立审美验收 |

## 采样、细节与缩放

- 物体图使用 Point 采样、不生成 mipmap；颜色、法线、深度、窗户编号图尺寸完全一致。
- 不用全屏降分辨率、屏幕像素吸附或模糊滤镜营造颗粒。物体可以连续移动。
- 像素物体以源尺寸放置。大小变体应在建模阶段制作并重新生成外观；禁止把已烘焙像素物体随机放大或缩小。
- 栏杆、细线、屋顶设备优先保留可读的体块；不因细节太小将某一栋升到8 PPU。
- 细节通常组织成2—3个像素以上的色块；单像素高对比白点应重点审查。该项需视觉验收，不能仅靠密度数值保证。
- 密度一致不代表复杂度一致。后续仍需统一窗格、明暗和纹理的节奏。

## 入库与打包检查

PixelDensityAudit 验证所有 PixelObjects 资源的标记密度、四向贴图采样、实际网格尺寸对应的像素密度和预制体缩放。ProjectValidation 调用该检查，密度混用会阻止打包。

Main 实际运行另检查已生成建筑与树木的世界缩放和密度，避免预制体合格但生成时又被放大的情况。固定种子1668065642复看旧楼、新楼同框、昼夜和运行中的外观。

统一颗粒度已获用户认可。2026-09-27 按此标准补齐第一批十款公寓；第一批完成时25套物体外观（23款建筑与2种树）使用同一密度。新增七款的实物截图位于 Art/Reviews/ApartmentBatch01/Completed，外观仍按批次等待用户验收。

第二批新增6款两至三层集合住宅，当前共31套物体外观（29款建筑与2种树），继续使用同一4 PPU标准；实物截图见 Art/Reviews/ApartmentBatch02/Unity。

2026-09-28：第三批C01—C06沿用4 PPU，当前37套物体外观（35款建筑、2种树）。其中6款旧公寓/住宅已停用但源文件及外观归档仍计入资产检查；检查总数不等于当前参与生成的款数。
