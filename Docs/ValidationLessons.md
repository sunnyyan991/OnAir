# 验证流程约束

## 2026-10-10：候选网格预览与既有许可

- Unity 在隔离环境中拒绝既有许可IPC连接时，不能把许可等待当成模型验证。确认日志原因后，使用能访问现有许可的编辑器环境执行已授权的小范围检查，仍保留硬性超时。
- 机场预览出现了CPU网格已更新、实际绘制仍使用旧数据的情况，`EditorUtility.CopySerialized` 更新已有Mesh后部分玻璃和构件缺失。改为保持原Mesh资源/GUID，`Clear` 后重新设置顶点、索引、法线和边界并上传数据，复渲染后玻璃和细节恢复。
- 几何检查PASS不代表造型验收通过。模型改动必须查看能回答问题的少量实际截图；因可见缺失而修正绘制数据，属于必要的定向验证，不扩展为全世界扫描。

## 2026-10-08：默认在 Unity 内验收

- 默认仅在 Unity Editor 内测试验收；用户明确要求打包时才执行打包，Development 和临时测试包也属于打包。
- 编辑器被占用或验证不方便，不构成自行打包的理由。此前运行包验收属于历史记录，不作为后续任务的默认授权。
- 何时需要打包测试的具体条件暂未确定，后续随实际开发逐步确认，不预设自动升级到运行包验收的条件。

## 2026-10-03：避免无效等待

- 自动验证必须有明确的停止条件和超时上限；长时间没有新日志、输出文件或状态变化时，立即停止并重新判断原因。
- 启动 Unity 验证前先检查是否已有同一项目实例占用。出现项目锁、重复实例或启动堆栈停留在初始化阶段时，不继续等待。
- 先做最小可证伪检查：资源解析、场景加载、首个地图切片和首帧画面。只有这些通过后，才运行较长的 Play 或生成验证。
- 验证脚本必须报告成功、失败或超时，不能以进程仍在运行作为成功依据。
- 后台进程、权限审批或日志读取异常导致验证无法判断时，明确标记为“未验证”，停止当前流程并换用更小范围的检查。

## 2026-10-04：按风险选择最小验证

| 改动 | 默认检查 | 升级条件 |
|---|---|---|
| 文档、编号、简单数值 | 差异、引用及对应计算 | 发现关联错误 |
| 单个模型或贴图 | 仅该资产烘焙、相关视角截图 | 改变占地/生成接口 |
| 阴影、光照 | 隔离场景比较关键状态，短时 Main 接入 | 发现随地图切换的问题 |
| 交通、生成、流式加载 | 固定种子有界运行，检查针对性指标 | 证据表明需多种子/长航程 |

先列出要回答的问题，一轮通过即结束。只要局部工具能回答，就不启动完整城市；不为截图反复启动项目，不重烘焙未修改资产。单次 Unity 工作必须输出明确结果并有硬性超时；编译错误或重复无进展先修因，不继续等待。正常日志只读摘要，详细原始日志保存到文件。

## 2026-10-13：机场接缝验证

- 中心路线连通和建筑净空通过，不能证明路口铺面、外边线和画线关系正确；应同时查看一个斜视路口近景和航站楼接缝近景。
- 检查实际铺面时，要区分预制体铺面与运行时机库前场。机翼采样点跨越两者边界，应逐点检查对应所有者，不能只按机身中心判断后把运行时机坪误报为空洞。
- 已采样的平滑曲线不要再逐点圆角细分，否则会放大路线长度遍历和几何检查的工作量。

## 2026-10-13：小机场截图与动作

- 纯逻辑/Main运行PASS之后仍要直接看实际图。普通Additive场景与layer31不能保证隔离：Main实例化渲染可能继续画城市道路与建筑。用真正PreviewScene、sceneCullingMask及batch空场景清理，避免污染图被当作模型问题。
- 维修快照应先刷新飞机/车辆/屋顶检视的显示状态；阶段刚切换且未经过LateUpdate时的即时截图不能代表实际可见性。
- 地勤车辆连续位移不代表互相避让；还应检查停车位入口及双向通道的最小间距，避免驶回车位时穿过其他已停设备。

## 2026-10-14：机场夜间材质与灯具

- 不用材质名字包含 `Light`、`Warm` 等字样推断发光身份；这会把浅草地、木材和象牙色机身误选成灯。导航镜片单独建组，普通建筑窗光使用精确身份和所属建筑。
- 灯具材质克隆必须改成明确的灯具名，避免继承机身材质名后令验证误报。机场状态从 `flight.airport` 连接读取，不假定控制器与飞机组件在同一对象。
- 透明屋顶会暴露原先看不到的几何问题。机库底板与共享机坪同高时，两个受光面在强光下形成条纹；保留唯一可见地面，模块底板应在其下方。
- 该轮只生成一个机场、检查屋顶透明端点与中间态、双向灯光规则以及短时暂停Main夜景。发现上述具体问题后仅复查对应状态，通过后结束；不重跑完整维护等待或全资产烘焙。

## 2026-10-14：机场外围生成与地块所有权

- 资源加载范围不能作为建筑、水系的排除范围。实体围栏、限高邻域和加载范围分开；接路必须验证终点确为现有道路，至少覆盖一处沿海反例及反向跑道。
- 机场地面由预制体提供时，世界地面、水面、岸壁和岸边条带都应对实体核心做精确差集。只裁水平面仍可能留下一条高出草地的护岸；只裁整格又会造成围栏外缺地。
- 本轮限定一个机场重建、三种子各双向的接路检查、顺序闪灯昼夜帧及短时Main维护截图；已通过后不重跑完整降落或15分钟维护。截图检查实际铺面接缝，人口检查实际资产高度与完整占地，均不以中心点替代。

## 2026-10-14：铺面边界反馈与小飞机

- 用户说铺面衔接自然，首先应把材料边界贴齐，不自行把柏油变成尖舌或让水泥退让成凹口。覆盖采样只能证明有地面；仍须看三处入口和圆弯端点的实际近景，确认形状符合反馈。
- 同一机场的静态小飞机只重建本批模型，检查实际尺寸、接地点、三角面数和停机灯状态，再短时检查Main；不因新增装饰重跑整个机场起降流程。效果图先生成，尺寸以米制模型和当前玩家飞机比较为准，不把概念图透视当尺寸依据。
