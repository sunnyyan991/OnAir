# 建筑重复与移动采样

## 建筑选择

检查发现：临街行原来只对上一次规则ID给予0.45倍权重；后排填缝没有同款抑制。后排同时受剩余进深、宽度、4层高度上限及地形限制，更容易只剩少数候选。因此，成排重复既有资产覆盖不足的因素，也有两条生成路径不一致的因素。

调整：同一地块的前排和后排共用 BuildingDiversityPicker。按实际 prefab_id 识别同款，降低近期四次已选款的权重；同款连续两次后，若存在另一种合格建筑，下一次排除该款。仍保留街区权重及住宅同类聚集倾向，不修改可放置判断、尺寸、地块或资产池。

只有一种款式能放下时允许重复，不留洞、不缩小建筑、不挤压占地。记录总选择数、单款候选次数、连续重复和无替代时的重复，供后续判断应补哪些小面宽/浅进深款式。这是地块内选择顺序的保护，不保证跨地块、跨行的视觉上绝不会出现三栋相似楼。

## 移动时细线变化

Game相机为固定角度正交投影，位置连续移动；建筑不按屏幕像素跳格。当前4 PPU的贴图在屏幕上并不总对应整数像素，原先Point硬采样会使细线在移动中交替变宽、变窄。

新增像素边界采样：仅在约一个屏幕像素宽的交界带内计算相邻颜色覆盖，像素内部保留固定色块。原贴图仍为4 PPU、Point、无mipmap；运行着色器分别算出邻近像素的最终光照颜色，再按屏幕覆盖混合。深度、法线和窗户ID仍用离散采样，避免不同建筑深度或灯窗标识被混合。没有低分辨率整屏放大、相机像素锁定、时域历史或全屏模糊。

代价是增加相邻像素的颜色和光照数据读取；复用同一次阴影查询和单一深度值。目标是降低移动时的高频跳变，不能宣称完全消除所有轮廓、遮挡、阴影或帧率导致的抖动。在小尺寸屏幕上，一个贴图像素小于屏幕像素时，清晰细节与稳定性仍有取舍。

验证：MotionDiversityReview 使用真实Unity渲染的同一资产、相机、灯光与48步亚像素平移，对比旧硬采样和新边界采样；输出连续帧、动态HTML对照及时间二阶差分RMS。这个指标只度量测试条件下的突变，不等同于用户感受或整机性能测试。
