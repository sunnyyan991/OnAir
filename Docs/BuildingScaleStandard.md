# 建筑统一比例尺

2026-09-28：暂停新款资产制作，先统一已制作的 A01–A10、B01–B06、C01–C06，共 22 款。旧资产只作为尺寸对照，不改源模型、贴图或权重。

## 唯一项目尺度

- **1 Unity 世界单位 = 1 米**。这是项目制作约定，不是对现实所有日本建筑尺寸的断言。
- 住宅统一层高 **2.65 米**，从一层楼面到下一层楼面。两层主体高 5.30 米、三层 7.95 米、四层 10.60 米；基础、坡屋顶、女儿墙和设备另计。
- 地块规划模块 **0.25 米**。已有通过验收的非整模块尺寸不强行取整；占地向上取模块数用于规划。
- 像素密度仍为 **4 PPU**，一个像素对应投影平面 0.25 世界单位，不能靠改变单栋图片清晰度或缩放成品来纠正体量。
- 建筑根节点和游戏实例始终为 **(1,1,1)**；编辑源模型后重新生成四个方向的颜色、法线、深度和灯窗图。
- 住宅门扇约 2 米高，外廊/阳台与层高对齐。单户住宅与公寓采用同一人体尺度，不能整栋等比缩小而把门、楼梯和层高一起缩小。

## 必须区分三个尺寸

1. **楼体**：实际住人的主体外包尺寸，不含院落、屋顶挑檐、阳台和外置楼梯。L 形和退台楼记外包尺寸，不等于实际建筑面积。
2. **地块占地**：包含院子、台阶、挑檐、阳台和楼梯的完整包围范围。生成器必须使用这个尺寸，不能只按主体塞入街区。
3. **总高**：从地面到屋顶/屋顶设备最高处。不能把坡屋顶高度算成额外楼层。

类型含义：A 是中层多户公寓；B 是低层多户住宅，不是一户建；C01/02/03/04/06 为单户住宅；**C05 为三个独立入口的连排住户，总宽不可与单户直接对比**。

## 防止再次失衡

- `BuildingScaleStandard` 是层高及单位约定的代码来源；所有新住宅生成器引用同一层高。
- `BuildingScaleAudit` 在源模型合并前测量住人主体，对照明确的每款尺寸表；不从图片估算大小。
- `BuildingScaleManifest.json` 保存测量值、实际占地、总高、楼层和源模型指纹。打包验证会检查 22 款是否缺失、模型是否改后未复核、占地是否包住几何、像素密度是否一致。
- 新款进入资产池前，必须登记类型、层数、主体尺寸、完整占地，再与已有独栋/低层公寓/中层公寓放在**同一镜头、同一缩放**下验收。禁止把每栋单独放大到填满格子后用来判断比例。
- 本轮固定镜头对照 `Art/Reviews/BuildingScale/Before` 和 `After`：上排 A01、B01、B03，下排 C01、C03、C05。所有格子使用相同世界比例。
- 正式场景还需检查实例单位缩放、占地重叠、不同类型共存和日夜截图；静态模型检查不能代替实际摆放检查。

不采用“全部住宅缩小一半”的处理：旧资产中的 JP_002 为单户，JP_012 为窄面宽单户长屋模块；新 C05 是三户整体，原对比混入了不同户数。问题主要是独栋的横向体量和完整地块偏宽，不能据此把所有层高一并减半。
