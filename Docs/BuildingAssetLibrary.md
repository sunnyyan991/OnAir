# 建筑资产目录维护

统一入口：Art/AssetLibrary/index.html。资产编号按用途大类、用途子类、三位序号制定，详见 AssetNumberingStandard.md。目录展示名称、编号、子类、状态、缩略图、权重与兼容资源路径；历史编号只作为追溯映射。

assets.json 维护具体资产与评审状态，categories.json 维护类目，template.html 维护界面。通过 Update-AssetLibrary.ps1 同时生成 HTML、BuildingAssetRegistry.csv、AssetCodeMigration.csv，禁止在导出表各改一套名称。HTML离线可打开，内嵌数据，无需服务器。

当前50款新资产记录：38款已制作建筑（五套秋叶原商业建筑已入池），6款独立广告内容，6款规划建筑。详见 AkibaCommercialAssets.md；规划办公4款、街区百货及社区商场2款继续保留。

2026-10-03新增独立“旧建筑资产评估”区域：legacy-assets.json列出尚未进入新资产目录的25款历史运行资源，包含5款当前城市仍启用旧款、8款已停用旧款、12款海岸/沙漠旧模式资源。只按原用途类别和运行ID整理，不另造编号。默认显示城市旧款，用户可切换全部、停用、区域模式及用途筛选；每款提供白天、背面、夜间实际资源截图，以及占地、总高、规则权重、资源路径。

旧资产渲染类型记录在rendering：早期未烘焙模型按原模型渲染，已烘焙款按游戏PixelObjectView渲染，不为截图重做外观。截图自动取景，不能用缩略图占比比较建筑实际大小；夜景用于外观预览，不作为随机窗灯覆盖率验收。选择“保留/替换”存于浏览器本地，可导出评估CSV；该操作不改游戏资源或权重。LegacyBuildingReview.Run生成截图与清单，Update-AssetLibrary.ps1将新旧清单分别内嵌到同一HTML；validate-library.cjs检查筛选和截图完整性。

每批六款，类型卡与效果图确认后制作源模型，统一四向4 PPU像素外观，检查楼体、完整占地、总高、入口、楼梯、栏杆、屋顶、配色与实例随机夜灯；提供同镜头日夜和行进截图，验收后替换同用途旧款。目录缩略图不是游戏截图验收。

比例分别记录地块面积目标、街区内建筑栋数建议、运行基础权重和实测出现比例。HTML中地块建议尚未写入生成器，不冒充东京统计值。诊所目录归PUB-MED，历史运行仍属Shop；此差异已在资产说明登记，后续医疗生成规则接入时单独处理。

运行数字ID、CSV资源键与已有Unity资源路径保留为兼容映射。新款使用新用途编号命名；既有路径不直接改名，避免破坏生成器、尺度清单和GUID引用。老模型停止生成与删除文件是不同阶段。

工具：BuildingLibraryReview.Run读取目录中每个已有预制体路径，按其新编号导出缩略图并执行像素密度、既有住宅尺度与替换规则检查，然后执行Update-AssetLibrary.ps1同步目录。新增款式先在目录登记稳定编号，不能仅有图片就标成已入池。
