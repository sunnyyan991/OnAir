# 自动存档与恢复

## 使用方式

普通运行先进入标题。START 选择槽位开始新旅程；LOAD GAME 选择已有存档继续，启动本身不读取为活动旅程、不推进航程，也不写玩家槽位。默认 3 槽，可通过 `GameEntry.saveSlotCount` 调整为 1–8。完整菜单流程见 [标题与运行设置](TitleMenu.md)。

首屏先显示标题，再分帧准备背景：无可用存档时显示固定起点；有存档时只读最近成功保存的兼容快照，显示它的位置、飞机姿态、天气与时段。标题预览不绑定活动槽、不补存、不累计离线时间；返回标题选择不保存时，背景仍来自最近落盘位置。点击开始或读档后显示实际地图准备进度，地图完整后才进入飞行，均在 Main 中完成。

活动旅程保存航程、飞机游移进度、天气及剩余时长、昼夜进度、玩家暂停状态、附近建筑布局和已经发布的高架道路。面板展开状态与世界详情开关单独保存。右侧面板显示存档状态。离开确认使用的临时暂停不写入存档。

离线不推进航程、天气和昼夜。左上角现实时间仍显示电脑当前时间。车辆、云和降水重新生成；未来天气重新随机，不保证与退出前尚未发生的天气序列一致。

NEW SEED 在当前槽开始新旅程并留下上一段旅程；PREVIOUS FLIGHT 返回上一段旅程，同时把离开的旅程作为“上一段”。每槽只有一个当前旅程和一个上一段旅程，不建立无限历史列表。RELOAD CSV 改变生成规则时，会保留改动前的旅程；不同配置的旧旅程不能直接载入，以免建筑与道路出现错位。

世界首批可见地块完成后首次保存；START 的初始保存成功后才进入飞行，失败可 RETRY / BACK。默认每 30 秒保存一次，`GameEntry.autoSaveIntervalSeconds` 可调整，最低 5 秒；手动调整天气、时间、暂停、路线和面板后延迟约半秒保存，避免拖动时连续写文件。NEW SEED 保留这些自动保存规则。活动旅程切到后台、暂停应用或正常关闭时立即保存。地图正在准备下一批内容时，沿用本旅程最近一次已提交的布局，保存最新航程与气候，不强制同步生成地图。没有任何已提交布局的新旅程需先完成首批地块。强制结束进程或断电只能恢复到最后一次已完成的保存。

SAVE GAME 可立即保存。返回标题或退出时，有未保存变化便显示保存 / 不保存 / 取消确认；保存失败不离开。不保存离开先完成已发起的写入，再禁用新的自动保存与生命周期补存，保留最近一次成功快照。标题只展示背景，不继续保存。

## 文件位置

使用 `Application.persistentDataPath/Saves/`，Editor 与 Player 分开。当前 Windows 配置下：

```text
%USERPROFILE%/AppData/LocalLow/DefaultCompany/OnAir/Saves/
├── Editor/                 Unity Play 的存档
└── Player/                 Windows 运行包的存档
    ├── settings.json       面板设置，所有槽共享
    ├── display.json        显示设置，所有槽共享
    └── Slots/
        ├── 01/
        │   ├── journey.json         当前旅程
        │   ├── journey.bak          上一次完成的保存
        │   └── previousJourney.json 上一段旅程
        ├── 02/
        └── 03/
```

首个存档同时创建备份。备份用于损坏恢复，上一段旅程用于主动换图，两者职责分开。

旧版本位于 Editor / Player 根目录的 journey.json、journey.bak 与 previousJourney.json 保留原文件；读取列表提供 LEGACY FLIGHT / PREVIOUS FLIGHT 兼容入口。明确读取后，新保存分别写到 `Slots/LegacyCurrent/` 或 `Slots/LegacyPrevious/`，不自动迁移或覆盖根目录旧文件。滚动备份不作为额外槽位。减少配置槽数不删除已有槽，仍显示 1–8 范围内实际存在的存档。

测试参数 `-onairSeed 数字` 默认禁用保存；批处理运行同样默认禁用，避免影响日常旅程。显式传入 `-onairSaveDirectory 绝对目录` 可开启隔离测试存档，并覆盖默认位置。固定种子用于 START 创建旅程；LOAD GAME 仍按所选存档恢复，不改写它的种子。

## 模块职责

| 文件或模块 | 职责 |
|---|---|
| `Game/GameEntry` | 连接各模块与配置，初始化标题及背景；选择槽后再准备活动旅程 |
| `Game/SaveController` | 当前槽绑定、加载、提交、自动保存、上一旅程切换、失败反馈与退出保存 |
| `Data/Saves/SaveSlots` | 只读列槽、元数据与旧档路径映射 |
| `Game/MenuController` | 标题与槽位选择、覆盖确认、临时暂停及离开处理 |
| `Data/Saves/SaveData` | 纯数据结构，不保存场景对象或资源引用 |
| `Data/Saves/SaveFileStore` | 校验、文件大小限制、临时写入、替换、备份与保留异常文件 |
| `Data/Saves/SaveMigration` | 格式版本、配置指纹与数据有效性检查 |
| Journey / Flight / GameSession | 分别导出和恢复路线、飞机状态及气候状态 |
| TerrainStreamer / WorldPopulationCache / WorldLayerHighways | 恢复附近布局与发布完毕的道路，按当前位置重建所需地块 |
| FlightPanel | 面板设置与存档提示、旅程切换入口 |

建筑使用 `buildings.csv` 的数字字符串 id 定位预制体，不依赖场景实例 ID、数组顺序或资源路径。附近建筑保存位置、旋转、颜色和道路占地；高架道路保存几何、桥墩、入口和连接关系。路线随机数发生器显式保存状态，恢复后不从起点重演全部路线。

截取一致的数据在主线程完成，JSON 序列化与磁盘写入放到后台。Unity 6000.3.25f1 的 JsonUtility 底层标记为线程安全，保存数据不含 UnityEngine.Object 引用。[Unity 对应版本源码](https://raw.githubusercontent.com/Unity-Technologies/UnityCsReference/6000.3.25f1/Modules/JSONSerialize/Public/JsonUtility.bindings.cs)。生成中的协程和未发布的道路不写入文件。

## 损坏与兼容

先写 `.tmp` 并刷新到磁盘，再替换正式文件并保留前一版备份。文件有 SHA-256 校验，最大 16 MiB；校验只用于发现损坏，不是加密或防作弊。

主档损坏时尝试备份；恢复后第一次保存前，把损坏主档另存为 `.rejected-随机编号`。两份都不可读时，保留文件，在 LOAD GAME 中提示失败，不绑定活动旅程、不自动覆盖。玩家通过 START 明确确认覆盖该槽，才允许准备新旅程；不可读旧文件另存为 `.previous-随机编号`。地图准备及成功写入之前不删除旧主档。

可读但属于更高版本、不同生成器或不同配置的存档也停止自动覆盖，不静默回退到更早备份。面板设置独立检查，其格式不兼容不会阻止旅程保存。

当前格式版本为 1，没有已发布旧版本需要迁移。未来升级格式时，在 SaveMigration 中加入明确转换；无法可靠转换的布局保留原文件。配置指纹包含三张规则表、建筑映射与占地、地形套件及昼夜/天气配置。修改算法时更新 `ContinuousWorldPlan.GeneratorVersion`；修改未被指纹覆盖的资源布局或套件内容时更新 `SaveMigration.ContentVersion`。

标题菜单更新仅增加可选的保存时群系名，保持格式版本 1；原有旅程快照仍可读取。

## 验证

本次使用独立工程、种子 1372 和项目内测试存档目录，正式 Main 场景及其他任务改动保持原样。验证范围是一次中途航程保存与跨进程恢复、上一旅程切换、损坏恢复、不可读及更高版本保护，并补充路线随机状态、建筑 id 和高架连接恢复检查。不进行完整巡航或多种子扫描。

2026-10-05 初版存档验证结果（标题菜单接入前）：

- Main 保存与跨进程恢复通过：非起点航程、飞机位置及游移阶段、夜雨与暂停状态、附近建筑 id / 占地 / 朝向 / 颜色、道路占地一致。
- 上一旅程切换通过；主档损坏时读备份并保留损坏文件；两份坏档和更高版本主档停止自动覆盖，即使存在旧备份也不回退更高版本。
- 12 次后续地形推进与未中断路线一致；独立高架几何、桥墩、入口和引用连接恢复通过。
- 地图准备期间保存最新航程、切到后台即时保存、返回上一旅程后立刻退出、后台序列化、异常主档在换旅程前保留通过。
- Windows x64 正式包构建通过：0 错误、2 条现有警告。实际运行包两次启动验证自动保存与重启读取通过，无运行错误。正式 Main 文件和其他任务文件保持原样。
