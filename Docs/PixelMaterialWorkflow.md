# 物体级像素外观 · 2026-09-26

## 当前实现

Main 保持原生分辨率、连续镜头和连续移动。整屏 PIXEL 2X / 3X 没有恢复。

现有 13 种日式建筑与两种城市树木，已从各自的原始模型生成独立像素外观，每种保留四个朝向，共 60 套。窗格、阳台、屋顶和物体轮廓的像素属于物体本身，不再跟随屏幕网格重新量化。原模型仍作为制作源和投影源。

这一步解决“整个城市仍然只是高清几何”的基础表现问题，不等于已经完成《西奥小镇》品质的手绘资产库。现有楼型的细碎屋顶、阳台密度和重复感仍需逐类做美术整理。道路、河岸、高架与飞机保留当前几何表现，尚未统一为独立像素图像。

## 制作与维护

- 制作源：现有 JP 建筑预制体；修改模型后执行 PixelObjectBaker.Run 重新生成。
- 输出：Assets/Art/PixelObjects，每个物体独立目录；重烘焙保留已有资源 GUID。
- 密度：每个世界单位 4 个像素；Point 采样、不使用贴图 mipmap。轮廓与颜色块在物体空间固定，画面没有低分辨率中间缓冲。
- 每套包含颜色、法线/窗灯分类、深度与表现网格。深度用于遮挡其他建筑与飞机；法线用于昼夜和天气照明；窗灯独立发光。
- PixelObjectView 在摆放旋转确定后接入外观。原网格仅投影；运行时不重新烘焙建筑。建筑调色仍沿用共享色板材质。
- 适用当前固定俯视镜头和四向建筑摆放。Scene 显示原模型；不兼容的相机自动回退原模型。自由旋转像素镜头或任意建筑旋转仍需要新增视图方案。

## 验收

PixelCityReview 检查全部 JP 资产引用、运行中的像素外观、原生相机输出、白天异常黑块、连续飞行可见地块完整性，并输出同位置旧外观对照、两种尺寸白天图、移动图和夜景。

截图及报告位于 Art/Reviews/PixelCity。独立程序另检查晴雨转换、五个时段、夜间窗灯与三次换种子。测试计时含强制渲染和读回，不代表正常窗口 FPS，也不构成长时间功耗结论。

## 后续美术工作

先整理四层公寓的窗格节奏、阳台和屋顶，减少自动烘焙留下的细碎像素；以正常城市镜头与移动观感验收，再扩展办公楼、商店、商场和住宅。像素轮廓已经可用，但《西奥小镇》那种清楚的形体与色块组织仍需要有意识的美术制作，不能仅靠采样参数完成。

## 本次实测（2026-09-26）

- 编辑器实际连续运行 1020 帧；场景中 2344 个像素对象、1536 栋建筑；可见地块缺失 0、紧急补块 0，最长生成准备步骤 6.78 ms。
- Windows 开发版构建成功，运行验收通过：晴雨切换、五个时段、夜间窗灯、三次 NEW SEED，均未发现可见地图空洞。
- RTX 2060 / i7-9750H，带强制渲染与 GPU 读回的短测：640×480 中位 4.82 ms、p95 8.19 ms；1280×720 中位 10.70 ms、p95 17.90 ms。这不是正常屏幕 FPS 测试。低分辨率阶段仍录到一次 932.62 ms 长帧，不能据此宣称所有卡顿已消除。
- 首屏世界准备 6.85 秒（首次强制渲染之前）；三次换种子 3.45–4.36 秒。阴影仍依赖原始几何，后续性能优化必须另测。
- 最终输出：Builds/WindowsNative/OnAir.exe。实际截图和原始报告：Art/Reviews/PixelCity/player。
