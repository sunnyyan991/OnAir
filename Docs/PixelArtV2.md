# 像素资产架构自查与第二轮绘制 · 2026-09-26

## 结论

现在的表现是有深度信息的固定视角图像，并非任意视角都成立的三维外观。在 Game 中，颜色、表面方向与深度共同重建建筑的可见表面；原始模型、占地、建筑高度及投影源仍保留。在 Scene 视角里看到倾斜片体，属于表现载体，不等于源建筑被删掉。

本轮增加相机适用性检查：Scene 编辑视角显示原模型；正交相机与绘制角度一致时使用像素外观。其他相机角度、透视投影回退到源模型。非 90 度建筑朝向、非等比缩放或不完整的四向资源不启用像素外观，以免形成错误遮挡。

| 扩展内容 | 当前方式能否支持 | 需要做什么 |
| --- | --- | --- |
| 新增高楼、窄楼、长条楼、异形静态楼 | 可以 | 保留完整源模型，设置占地/高度，绘制四向外观并审核深度与落地位置 |
| 调整楼色、窗格、阳台、屋顶 | 可以 | 修改源资产与像素绘制规则，重新生成；源几何摘要会提示旧外观失效 |
| 改变屏幕分辨率、正交缩放 | 可以 | 不改变图像所属的物体空间；近远景可读性仍需检查 |
| 自由旋转或透视镜头 | 当前像素图不支持 | 已回退源模型；若以后要保留像素外观，需要更多方向或改用三维像素材质 |
| 45 度楼房朝向、倾斜、非等比缩放 | 当前四向图不支持 | 回退源模型；美术入库时新增相应方向或独立变体 |
| 转动风扇、开门等模型动画 | 不会自动随静态图更新 | 动态部件单独渲染或制作动画帧 |
| 碰撞、射线点击、飞行避让 | 不能使用片体当建筑实体 | 继续依据源模型/占地/高度；深度图仅负责视觉遮挡 |
| SSAO、屏幕反射等新渲染效果 | 尚未验证 | 当前只写前向颜色与深度；启用新效果时补查深度/法线预通道 |

原模型仍承担阴影，故不能把片体数量较少等同于所有三维开销已经消失。相机回退是编辑和扩展保护，不是自由旋转像素相机已经制作完成；回退模型使用其原始材质，艺术表现可能不同。

## 美术参考与本项目采用的规则

参考《西奥小镇》社区的[建房流程](https://forum.theotown.com/viewtopic.php?t=13515)、[明暗、阴影与细节教程](https://pca.svetikas.lt/docs/guides/graphics/a-better-visual-guide-on-shading-shadows-and-detail/)（原作者教程转载）及用户提供的城市图。

教程强调先形体后细节、两侧明暗关系、暗色窗玻璃、窗台深度、女儿墙与克制的纹理。这些是参考依据；以下为本项目的具体美术取舍：

1. 保持已认可的日式楼型、比例和当前镜头，不把整个场景重新铺到屏幕像素网格。
2. 窗格用灰蓝暗玻璃、有限的顶部反射和下沿暗部形成成组色块。日间不把玻璃画成鲜亮蓝色。
3. 阳台板、楼层带、女儿墙连续；小于可读像素簇的栏杆、通风栅格和落水管不进入像素外观。
4. 屋顶保持明确的大灰面与少量设备体块。木材、遮阳棚与混凝土各有有限色板。
5. 采用覆盖率占优的表面确定像素，不把玻璃、白墙和背景混成模糊边缘；仍使用 Point 采样。
6. 只在遮挡接触位置添加克制的暗部，不给整座楼描黑边、不铺随机白色噪点。
7. 保留动态太阳。参考图的固定明暗用来研究形体，但不把太阳方向永久画死在贴图上。

这轮是基于自有模型、部件语义与像素绘制规则的重新整理；不是复制《西奥小镇》的图片，也不是宣称已完成逐像素手工绘制的最终资产。

## 夜灯

所有可识别玻璃都有独立窗户编号，包含以前固定为不发光的玻璃。随机结果由地图种子、建筑的全局地址与窗户编号决定，按住宅/办公/百货设置不同入住率，并有小幅整栋差异。相同楼型不再共享唯一的亮窗图案。

窗灯以整扇窗为单位，少量色温与亮度差异；不按每一帧或每一像素重新抽签。浮动原点、相机移动、同种子同地点重建后保持一致。使用共享材质和全局地图坐标，不为每栋建筑建立独立材质或逐帧随机数组。

## 入库与验收

源模型 → 建筑分类/占地/高度 → 像素绘制规则 → 四向颜色/法线/深度/窗户编号 → 单栋昼夜预览 → 游戏内验证。不要只画一张改变了轮廓的 PNG 而不更新深度与投影源。

源资产仍在 Assets/Prefabs/Buildings 和原有 Art 分类；生成结果在 Assets/Art/PixelObjects。PixelObjectBaker 保留已存在资源的 GUID；PixelArtAudit 检查源几何摘要、四个方向、像素深度范围、窗户编号、固定视角限制及实际渲染的夜灯稳定性。新增楼型进入目录后使用同一流程，不需要用户手动摆放这些片体。

实际截图与审核结果：Art/Reviews/PixelArtV2。不得把自动结构测试通过当作最终美术质量已达到参考游戏。

### 新资产的额外边界

本轮绘制针对现有静态、按材质分组的建筑。任意导入模型的复杂 PBR 贴图、透明玻璃、贴图招牌、LOD 组合、蒙皮和动画，不会自动完整转换，需要在入库时单独处理。特别是不能假设一张概念图或任意网购模型能直接变成四向且深度正确的像素建筑。新增超高地标还需复验飞行安全高度与相机裁剪距离。

原位静态摆放时检查旋转与缩放；运行中让建筑自身连续旋转或变形不属于当前支持范围。相机回退解决的是视角不兼容时的可见性，不是这些动态资产的完整解决方案。

## 最终验证结果

- 13 种建筑的四向深度、落地高度、源几何摘要与窗户编号审核通过。
- 四栋相同公寓的实际亮窗图案均不同；模拟 64 米浮动原点位移后，480000 个渲染像素中变化数量为 0。相机角度回退与非法朝向/缩放检查通过。
- Main 连续运行 1020 帧，可见缺块 0、紧急补块 0；检查首帧与后续截图，白天异常黑像素为 0。
- 最终 Windows 开发版通过晴雨变化、五个时段、夜间窗灯与三次 NEW SEED 验证。实际运行图位于 FinalPlayer；审核原始结果为 audit.txt、City/validation.txt、FinalPlayer/validation.txt。
- RTX 2060 / i7-9750H 的带强制渲染和 GPU 读回短测：640×480 中位 4.59 ms、p95 7.30 ms；1280×720 中位 10.72 ms、p95 17.50 ms。此计时不是常规窗口 FPS。测试保留一次 377.72 ms 长帧记录，不能宣称所有卡顿已消除。
- 首屏世界准备 6.75 秒，三次换图约 2.97–3.49 秒。美术改造未减少可见建筑数量；本次相机判断缓存与日间跳过灯光随机计算避免了额外重复开销。

生成资源、正式 Main 和 Builds/WindowsNative/OnAir.exe 均已更新。完整艺术表现仍需后续逐类型精修，不以自动审核代替用户审美验收。
