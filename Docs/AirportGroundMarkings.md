# OnAir 机场地面画线规范

2026-10-13。当前适用 ENV-AIR-002 SmallField、后续机场模块及运行时维修机坪；ENV-AIR-001 羽田式机场参数作为历史制作规范保留。1 Unity 单位 = 1 米。

这是供本游戏制作资产的规范：保留机场标识的含义与方向关系，尺寸允许为像素可读性简化。机场总体布置、飞机运动和管制流程仍是休闲游戏的近似表现，不作为真实机场设计或运行依据。


## 当前 SmallField 画线配置

2026-10-13起运行资产为ENV-AIR-002；以下历史羽田参数不直接套用到新小机场。新跑道240×18米：入口各6条1.2×12米白条，白色边线/中心线宽约0.28米；12/30编号。滑行道12米宽、圆弧12米半径，单黄中心线约0.28米，裁在跑道之外；地勤车位和道路白线约0.10–0.14米。所有机坪/滑行引导来自SmallAirportNetwork，运行时不追加重复路面。

机库地板与连续机坪同高0.19米，标线顶约0.21米；不重叠另一块厚底板。原机场完整制作规范与参考资料保留在下文和归档中。

## 调研依据

- 日本国土交通省《陸上空港の施設の設置基準と解説》，2024 年版，3.12.5–3.12.6、PDF 第 70–83 页：黄色引导线沿前轮通行位置布置，机位引导线和停止横条均为 0.3 米；停止横条通常为 6 米；机位需要表达进入、转向、停止位置及编号。黄线与跑道入口、编号、接地区和目标点等白色标识冲突时，应省略冲突黄线。[官方 PDF](https://www.mlit.go.jp/koku/content/001736131.pdf)
- FAA《Airport Marking Aids and Signs》：跑道主要标识为白色，滑行和等待位置为黄色；滑行中心线为单根连续黄线，边界按用途使用双实线或双虚线；跑道等待标识为两实两虚，实线位于等待侧。[官方说明](https://www.faa.gov/air_traffic/publications/atpubs/aip_html/chap2_section_3.html)
- FAA AC 150/5340-1M 是上述说明引用的机场画线细则。[官方目录](https://www.faa.gov/regulations_policies/advisory_circulars/index.cfm/go/document.information/documentID/1035908)

不同国家、机场运营方和机位设备会有差异。本项目统一以下画风与参数，新增资产不要混用另一套比例。

## 现有问题与本轮整改

| 自查项目 | 原问题 | 整改 |
|---|---|---|
| 维护机库门口的“O” | 将入库掉头轨迹铺成沥青带，再与出库轨迹叠加，形成公路式闭合环岛 | 保留完整混凝土机坪；到达引导线止于对正横条；最后半圈转向不再铺专用道路或闭合黄线 |
| 粗细 | 静态中心线 0.5–0.7 米，运行时为 0.22 米，主次关系混乱 | 飞机中心线统一 0.30 米；边界和勤务标线更细 |
| 重复 | 固定滑行干道与当前访问曲线分别绘制，产生重复路线、铺面及标线 | 固定路网与飞机共用同一批曲线；预制体统一绘制，运行时不再另画访问道路 |
| 连接 | 机位连接曲线按固定行距生成，不能匹配不同体型与端部机位 | 每个机位根据实际坐标、朝向和飞机前轮位置生成连接与停止横条 |
| 冲突 | 黄线可能覆盖白色跑道标识；线条在接近跑道时突然截断 | 单独保护白色标识区域；黄线延入跑道连接段，冲突处裁切 |
| 边界 | 部分边线是单实线；交叉口边线像横向封住通道，浅角度交汇仍留内边 | 道路铺面做并集，从其外轮廓生成双黄边线，去掉内部及重复边；可穿越机坪边界使用双虚线 |
| 停机位 | 小飞机使用无明确意义的黄色三边框 | 改为黄色中心线、前轮停止横条和开放的红色安全边界 |
| 跑道入口 | 阈值条带过窄，间距与边线位置不协调 | 60 米跑道保留 16 条、每条宽 1.8 米，布置在边线内侧 |

“O”形标识本身并非在所有机场都不合法；此次删除的是没有必要的游戏沥青环岛，不是禁止现实中的回转区或专门圆形标记。

## 颜色和线宽

颜色使用非自发光 Lit 材质，随环境与阴影变化。这里的暖白与柔和黄色是本游戏的美术色，不要求用纯 RGB 白/黄。

| 用途 | 项目颜色 | 宽度/形态 |
|---|---|---|
| 跑道编号、入口条带、目标点、接地区 | 暖白 `#E1DFCA` | 成对/对称、保持用途对应的形状 |
| 跑道中心线 | 暖白 | 0.90 米；本游戏采用 30 米实段 + 30 米间隔 |
| 跑道边线 | 暖白 | 0.90 米；60 米跑道的中心位置为左右 29.55 米 |
| 滑行道、机坪、入库引导中心线 | 黄 `#D1B65C` | 0.30 米单实线 |
| 不可跨越的滑行边界 | 黄 | 两根 0.18 米线，中间净距 0.18 米 |
| 可跨越的机坪滑行边界 | 黄 | 同宽双虚线，实段 4.5 米，间隔 7.5 米 |
| 跑道外等待标识 | 黄 | 两实两虚，线宽 0.30 米；横向于进入方向，实线朝等待侧 |
| 飞机停止横条 | 黄 | 0.30 米 × 6 米，垂直于机位方向 |
| 地勤车道和设备区 | 暖白 | 一般 0.24 米；不作为飞机引导线 |
| 飞机/设备安全范围 | 红 `#AC6455` | 0.24 米；进入侧留开口 |

红色安全范围是本项目机坪的统一表达，不能代替跑道关闭标记、等待标识或禁入标志。板缝属于混凝土材质细节，用低对比灰色，不能画得像引导线。

## 几何与连接

1. 每条线必须先确定用途、所属路线和真实起止点，再生成网格。飞机引导线来自飞机通行路线；设备边框来自设备停放范围。
2. 全部坐标先在机场资产局部空间生成，再随整个机场旋转。禁止按屏幕横竖方向直接画线。
3. 中心线与路网在同一点相接，转向使用切线一致的曲线；不能画尖角、错位连接或任意斜线。等待横条、停止横条、安全矩形允许直角。
4. 固定路网只由一方拥有。飞机直接沿相同的永久曲线运行，不允许运行时独立 `PaintRoute` 重新铺设另一套路面或黄线。机库局部定位线、停止横条与跑道等待标记可由运行时生成。
5. 机场主滑行道保留其宽度；小飞机维修分支可较窄。铺面宽度与引导线宽度分别控制，不能把 30 厘米的线画成一条道路。
6. 机库正前方是可转向的连续机坪。保留实际滑行与牵引动作所需空间；最后半圈的对正动作不必画成永久回转环线。
7. 跑道白色标识优先。黄线不覆盖入口条带、跑道编号、接地区或目标点；本游戏也为白色中心线留保护带。
8. 草地、海面、建筑、桥柱上不画飞机引导线。联络桥必须先有连续铺面。
9. 线条优先使用连续条带网格。少量独立横条可用薄网格；不要沿弯道排列厚方盒，避免锯齿侧面、阴影和闪烁。
10. 地面线与铺面留稳定的高度差，不能共面。运行时机坪线约在 y=0.24 米，固定滑行线约在 y=0.205 米；这些是渲染层次，不代表现实油漆厚度。
11. 多条滑行道汇合时先做铺面并集，再画外边界。内部边不能穿过另一条道路，浅角度分叉同样处理；重合外边只留一个拥有者。闭合轮廓的双黄线须用首尾相接的偏移，不留接缝缺口。
12. 路口的铺面外缘可圆角扩宽以满足连续连接，但不能把草地岛整体抹平。飞机中心线仍服从实际曲线；扩宽轮廓不作为额外通行路线。

## 紧凑机场补充

- 跑道现为 800–1000 米，宽度仍为 60 米；缩短的是游戏距离，不缩放建筑或黄线线宽。
- 目标点距入口取 `min(400, 长度×0.25)` 米，接地区站数限制在本端半段内，避免两端条带重叠。这是休闲游戏压缩规则，不冒充现实跑道标准。
- 维修、航站楼、货运及远机位混凝土机坪保留自己的铺面拥有权。并集后的沥青按同一组凸多边形边界裁切，不能在混凝土上再次叠铺；机坪内保留引导标线。运行时只补维修前场及局部标记，不再生成访问沥青路。
- 压缩机场占地不得删除分叉、联络道、机坪支路和陆侧交通等特征。四条跑道各保留两处端部连接及两个 Y 形连接，Y 形连接由共用干段和两个平行道方向分支组成。代码的 32 个曲线片段不等于 32 个出口；玩家与永久路网复用相同曲线，全机场固定特征不随本次所用跑道删减。
- 分叉口采用圆滑中心线和连续铺面。交叉口内的双黄边线应留出开口，不能横向封住通道；分叉间保留草地岛，不能用一块过宽沥青覆盖所有空隙。
- T1/T2 机坪轴线对齐，中央细缝补齐混凝土，共用中心线直接贯通；取消两侧内端相互绕回的 U 形连接。航站楼至远机位、相邻维修前场之间用连续混凝土连接，车行线仍独立使用白色标识。
- 永久跑道连接同样遵守白色标识优先规则，不能因补回分支而覆盖入口条带、编号、目标点或接地区。陆侧停车线、车道虚线为白色，不与黄色飞机引导线混用。
- 机场布局与实际滑行时间见 [飞行流程](AirportFlightCycle.md)，本轮图和记录在原验收页面。

## 机位制作要求

- 机位中心线与飞机机身方向一致。停止横条按该模型的前轮位置定位，不能一律放在机鼻最前端。
- 引导线连接到可通行的滑行线；不同飞机长度、翼展和端部机位分别计算。不能只复制一条曲线再按固定行距重复。
- 机位编号放在线路侧方或进入处，避免挡住中心线、停止横条和服务通道。后续新机位按同一字号层级制作。
- 红色安全边界和白色设备区不切断实际飞机路线；设备与停放飞机不得进入机翼净空范围。
- 维修机库保留牵引定位线与停止横条，不用车辆停车框替代飞机机位。

## 程序和验收

- 共用参数：`OnAir/Assets/Scripts/World/AirportMarkingRules.cs`。
- 固定路网：`AirportTaxiNetwork.PermanentPaths()`；在 `HanedaAirportAssets` 中生成。
- 路面并集、裁切及外轮廓：编辑器工具 `HanedaAirportPaving`。固定道路统一宽 25 米，先合并后裁掉跑道与混凝土区域；运算发生在制作阶段，不放入游戏逐帧逻辑。
- 当前紧凑机场刷新：`HanedaAirportAssets.RefreshCompactFeatures()`，更新对应路网/机坪模块并对齐整座航站楼位置，保留建筑网格和 GUID。全套地面规范刷新仍使用 `RefreshGroundMarkings()`，不因局部调整重烘焙全部建筑。
- 维修机坪、机库定位/停止及等待标记：`AirportServiceScene`；其独立访问 `PaintRoute` 已移除。飞机运动由 `AirportVisitMotion` 复用固定曲线，路线版本为 5。
- 最小检查：资源引用/GUID、关键线宽、净空、四跑道双向连接；机库前场、航站楼机位和跑道连接处各看一张俯视图，再看机库白天/夜间实际视角。通过后停止，不等待完整 15 分钟维护或重复巡航。

当前路网整合检查入口为 `AirportOperationsReview.Cohesion()`，记录为 `Art/Reviews/Airport/Operations/cohesion-logic.txt`、`cohesion-main.txt`；本次通过状态以这些实际记录为准。`markings-logic.txt`、`markings-main.txt` 是此前画线整改记录，不代表本次并集路网已经通过。截图继续放在同一验收目录，不另建页面。尚不涉及真实 ATC 放行、所有备选飞机机型的实测净空、机场管制认证或长期性能测试。
